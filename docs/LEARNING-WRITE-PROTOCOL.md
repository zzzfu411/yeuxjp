# 学习数据并发写入协议

状态：所有清点的浏览器入口已迁移。4 类真实多标签竞争场景通过；完整发布回归结果见修复报告与最终日志。

## 边界与选择

继续使用现有受管 localStorage 数据和同步的嵌套事务。在浏览器操作入口增加统一的异步 Web Locks 独占锁。一个完整用户操作在获得锁之后读取最新快照，随后同步运行原有校验、读改写、失败回滚和通知。这样可保留原有 JSON 备份及损坏值保护，同时避免只在部分写入函数加锁。

最低层受管写入在真实浏览器中检查锁的持有状态，未进入协议的写入将失败，便于发现遗漏。模型和底层事务仍可在非浏览器测试环境中独立验证。没有 Web Locks 的浏览器不静默降级为不安全写入，而是保留已有数据并提供明确提示。

锁保护本版应用之间的协作操作；开发者工具直接改写、浏览器数据清除、旧版本不遵守协议的脚本不受该协议控制。升级后应重新加载其他旧页面。

## 必须覆盖的入口

| 入口 | 完整操作范围 |
| --- | --- |
| 首次设置与资料编辑 | 读取最新资料、保存、更新界面 |
| 课程 | 开始、恢复位置、提示、答题记录+错题+SRS+日历+步骤答案、完成、重练 |
| 专项测验 | 记录练习、掌握度、错题、SRS、日历，成功后才能前进 |
| 语法详情练习 | 相同协调锁内记录练习、掌握度、错题与日历；关闭详情后排队操作不再提交 |
| 复习答题 | 校验当前会话、练习记录、错题和 SRS 分级作为一个操作 |
| 假名和词汇标记 | 正向标记、排除标记与 SRS 同时更新；清空同理 |
| 词卡自评 | 练习记录、日历与 SRS 同时更新 |
| 复习管理 | 补入缺失项目、删除单个错题、清空错题 |
| 听力设置 | 更新或恢复默认，失败保持先前界面值 |
| 学习数据 | 备份一致快照、导入覆盖、全量重置与回滚 |

入口清点记录见 `output/learning-write-entry-inventory.txt`。底层 `writeManagedLearningStorage` 和 `removeManagedLearningStorage` 是统一防线。

## 实施验收

1. 所有异步返回值由调用方等待；等待期间的重复提交被阻止。
2. 取锁后重新读取持久状态，而不是提交取锁前的旧 JSON 快照。
3. 导入/重置与答题竞争时，已失效的课程或复习会话不得重新写入旧结果。
4. 两个标签同时答题、同时标记不同项目时，结果和标记均保留。
5. 竞争过程中写入失败的操作仅回滚自身修改，不覆盖另一操作。
6. 单元、真实浏览器、旧备份迁移、故障注入及完整发布链通过。

## 已实现的协调细节

- 锁名：`yasashi:learning:write:v1`，作用域为同源浏览器；等待超过 10 秒以可见错误结束，允许用户重试。
- 操作进入队列前捕获替换 epoch，获得独占锁后再次核对；导入或重置先更新 epoch，失败则恢复。替换之前排队的旧操作不执行。
- `runLearningWrite` 回调必须同步；锁内调用现有同步 facade 和事务，不再次获取锁。界面等待 Promise 后才显示成功、进入下一题或关闭确认框。
- 课程答题在锁内读取最新 attempt/步骤答案，避免两个标签把同一会话的一题计入两次；重练使用新 attempt，保留首次成绩。
- 标记在锁内读取最新手动集合、排除项与能力状态；清空、删除错题、自评、朗读设置、资料和数据导出也遵守相同边界。
- 协调 epoch 不是学习内容，不放入备份，也不随学习数据重置删除。受管学习键仍集中维护。
- 非浏览器模型测试可独立执行同步事务；真实浏览器低层写入没有锁会抛错，facade 以保存失败反馈。

## 验证证据与限制

`tests/unit/learning-write-lock.test.mjs` 验证 50 个排队更新均保留、替换失效、失败恢复/释放锁和不支持 API 时不执行写入。`scripts/verify-learning-concurrency.mjs` 在同一个浏览器上下文的 3 个页面中制造实际排队：不同假名同时标记、两个测验同时记录、同一课程题重复提交、重置先于旧标记提交。结果写入 `output/playwright/maturity-20260905/concurrency.json`。

原有保存失败、回滚失败、非法原始字节保留、备份迁移和跨标签会话失效测试继续保留。此协议只串行化参与协调的操作；浏览器在多键写入中崩溃、旧版页面直接写入、扩展/开发者工具修改数据不受锁保护。它没有宣称 localStorage 具备 IndexedDB 的抗中断事务语义。
